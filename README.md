# Bizdin Auyl - PMS + CRM гостиницы

Система управления гостиницей и сетью гостиниц в Казахстане: брони и шахматка,
заселение с документами, касса со сменами и Z-отчётами, хозслужба и ремонт,
гости и компании, сотрудники с правами по должностям, отчёты, журнал действий.
Тенге, часовой пояс Алматы, ИИН/БИН, телефоны +7.

## Что внутри

| Часть | Где | Технологии |
|---|---|---|
| Веб-клиент | корень репозитория (`src/`) | React 19, TanStack Router и Query, Vite, GSAP |
| API | `backend/` - самостоятельный сервис со своим образом | Node 22, Fastify 5, Zod 4, Drizzle ORM, PostgreSQL 17 |
| Контракт | `backend/openapi.json` → `src/api/schema.d.ts` | OpenAPI 3.1, тот же контракт для будущих мобильных приложений |
| Сквозные тесты | `e2e/` | Playwright: Chromium, Firefox, WebKit, iPhone, Android |

## Как работает

- **Регистрация.** На пустой базе вместо входа открывается регистрация гостиницы
  и её владельца. Дальше людей заводит владелец: должность выбирается из списка
  или вписывается новая, права - по разделам (просмотр или правка) и особым
  полномочиям. Временный пароль и PIN выдаются один раз, свой пароль сотрудник
  задаёт при первом входе.
- **Сеть гостиниц.** Владелец добавляет гостиницы в «Настройках гостиницы»;
  переключение - в меню под именем. Гости и компании у сети общие; номера,
  тарифы, касса, сотрудники и журнал - у каждой гостиницы свои, чужие данные
  закрыты и списком, и по прямой ссылке.
- **Ресепшен.** «Сегодня» - заезды, выезды и то, что требует внимания;
  шахматка с перетаскиванием броней; бронь с подбором свободного номера и
  расчётом цены по тарифу; заселение по шагам (документ, сканер MRZ, согласие,
  готовность номера), счёт, оплата с фискальным чеком, выезд со сверкой.
- **Касса.** Смена открывается после отметки прихода и принимает остаток
  прошлой; внесение, выемка, сторно с причиной; Z-отчёт с пересчётом наличных,
  расхождение - только с комментарием.
- **Хозслужба.** Доска номеров по этажам, распределение уборок, приёмка
  супервайзером («проверен» - только тогда номер продаётся), «Мои уборки» для
  горничной на телефоне, заявки на ремонт с фото и снятием номера с продажи.
- **Учёт времени.** Отметка прихода с телефона или на общем планшете
  (`/kiosk`, ссылка - в «Настройках гостиницы») по логину и PIN; табель.
- **Безопасность.** Access-токен 15 минут в памяти вкладки, одноразовый
  refresh-токен в httpOnly-cookie; второй фактор (TOTP) для управляющего и
  бухгалтера; пауза после серии неверных паролей и PIN - по учётной записи, а не
  по адресу гостиницы; журнал действий без удаления; сканы документов - с
  записью каждого просмотра.

## Запуск для разработки

Нужны Node 22, pnpm (через corepack) и Docker для базы.

```bash
pnpm install
pnpm db:up            # Postgres 17 на localhost:5433
cp backend/.env.example backend/.env
pnpm db:reset         # схема, миграции и демо-данные
pnpm dev:api          # API на :4000
pnpm dev              # веб на :5173
```

Демо-входы (пароль `demo12345`, PIN планшета `1234`): `owner` - владелец,
`senior` - старший администратор, `reception` - ресепшен, `callcenter` -
колл-центр, `supervisor` - хозслужба, `maid` - горничная, `tech` - техник,
`accountant` - бухгалтер.

## Тесты

```bash
pnpm test             # API: unit и интеграция на настоящем Postgres
pnpm e2e              # сквозные тесты: сами поднимают API и веб на своей базе
pnpm typecheck:all    # типы веба, API и тестов
```

- **API** (`backend/test`): сценарии гостя от брони до выезда, касса, права,
  изоляция гостиниц сети, гонки (30 броней одного номера разом, двойные оплаты,
  две смены одной кассы, две горничные на одну уборку), нагрузка (600 запросов
  чтения разом без единого 5xx).
- **E2E** (`e2e/`): каждый раздел глазами сотрудника; аудит вёрстки всех ролей
  на 1440 / 800 / 390 px в обеих темах (прокрутка вбок, размеры кнопок под
  палец, доступность WCAG 2 AA через axe); стресс интерфейса - процессор в 4-6
  раз медленнее, браузер без WebGL, сеть 3G, обрыв связи, утечки памяти, час
  работы страницы. Любая ошибка в консоли, исключение или ответ 5xx - провал.
- Firefox и WebKit (Safari, iPhone): `E2E_BROWSERS=chromium,firefox,webkit pnpm e2e`.

## CI

`.github/workflows/ci.yml` на каждый пуш и PR: API (типы и тесты на Postgres),
веб (типы, сборка, сверка контракта API с кодом сервера), E2E в пяти браузерах
и устройствах с отчётом Playwright в артефактах, сборка и запуск Docker-образа
API на пустой базе.

## Развёртывание

**Railway**: один проект, сервисы `Postgres`, `api` (репозиторий
[PMS-CRM_backend](https://github.com/madhaligaze/PMS-CRM_backend)) и `web` (этот
репозиторий), связанные переменными. Пошагово, с таблицами переменных -
[docs/deploy-railway.md](docs/deploy-railway.md).

**Свой сервер**:

```bash
JWT_SECRET="$(openssl rand -base64 48)" docker compose up -d --build
```

Поднимает базу, API и веб (nginx с прокси на API) на `http://localhost:8080`.
На сервере перед ним ставится HTTPS (и `COOKIE_SECURE=true`,
`PUBLIC_URL=https://...`). API применяет миграции сам при старте; первый вход
на пустой базе - регистрация гостиницы. Образ API отдельно:
`docker build -t bizdin-auyl-api ./backend`.

## Отдельный репозиторий API

Папка `backend/` зеркалируется в
[PMS-CRM_backend](https://github.com/madhaligaze/PMS-CRM_backend) через
`git subtree`: там она становится корнем репозитория со всей своей историей.
Правки делаются здесь, в монорепозитории; в зеркало напрямую не коммитят.

```bash
# один раз
git remote add backend https://github.com/madhaligaze/PMS-CRM_backend.git
# после изменений в backend/ (закоммиченных)
pnpm backend:push      # git subtree push --prefix=backend backend main
```
